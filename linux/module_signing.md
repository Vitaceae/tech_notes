# Linux Module Signing

讓 kernel 拒絕載入未簽章或被竄改的 kernel module。

Objective  
1. Prevent unauthorized and malicious module loading  
  Only kernel modules signed with the authorized private key and using the SHA-512 hash algorithm  
  can be loaded into the kernel.
2. Prevent rootkits  
  Even if an attacker gains root privileges, they cannot inject and execute malicious kernel modules  
  without access to the signing key.

```bash
MODULES=y
MODULE_SIG=y
MODULE_SIG_ALL=y
MODULE_SIG_SHA512=y
MODULE_SIG_FORCE=y
```

----
## Analysis

Verify the signing status of modules and confirm that they load successfully.

+ related kernel config
    + MODULE_SIG_ALL=y
    + MODULE_SIG_SHA512=y
+ Automatic signing of generated kernel modules at build time.
+ Signed modules can be loaded successfully.

```bash
$ modinfo foo.ko | grep -E 'sig_hashalg|signer'
signer:         Build time autogenerated kernel key
sig_hashalgo:   sha512

$ modprobe foo
```

Verify that unsigned, corrupted or forged-signed modules are rejected by the kernel.

+ related kernel config
    + MODULE_SIG_FORCE

```bash
$ cp /lib/modules/$(uname -r)/kernel/drivers/.../foo.ko ./unsigned_foo.ko

# Corrupt the signature marker at the end of the module to create an invalid signature.
$ python3 -c "
with open('unsigned_foo.ko', 'r+b') as f:
    f.seek(0, 2)
    size = f.tell()
    f.seek(size - 30)
    f.write(b'\x00\x00\x00\x00\x00')
"

$ insmod ./unsigned_foo.ko
Loading of unsigned module is rejected
insmod: ERROR: could not insert module ./unsigned_foo.ko: Key was rejected by service
```

## Sing and Validate Kernel Modules

Create a configuration file **x509.genkey**.

```bash
[ req ]
default_bits = 4096
distinguished_name = req_distinguished_name
prompt = no
string_mask = utf8only
x509_extensions = myexts

[ req_distinguished_name ]
CN = My Kernel Module Signing Key

[ myexts ]
basicConstraints = critical,CA:FALSE
keyUsage = digitalSignature
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid,issuer
```

Generate a fixed certificate file **signing_key.pem** with the above configuration file.

```bash
$ openssl req -new -nodes -utf8 -sha512 -days 36500 -batch -x509 \
    -config x509.genkey \
    -outform PEM \
    -out signing_key.pem \
    -keyout signing_key.pem
```

Validate the kernel module.

```bash
$ KO=".../foo.ko"
$ CERT=".../signing_key.pem"
$ modinfo $KO
...
signer:         My Kernel Module Signing Key
sig_key:        2F:42:...:AB

$ openssl x509 -in $CERT -subject -issuer -serial -fingerprint -sha1 -ext subjectKeyIdentifier
...
issuer=CN = My Kernel Module Signing Key
serial=2F42...AB
```

Sing a module manually(產生憑證時已包含公鑰，故輸入參數使用同一個檔案)

```bash
$ KO=".../foo.ko"
$ CERT=".../signing_key.pem"
$ SIGN_TOOL="<kernel_path>/scripts/sign-file"

$ $SIGN_TOOL sha512 $CERT $CERT <YOUR_KO_FILE>

$ modinfo $KO
...
vermagic:       5.15.197-yocto-standard SMP preempt mod_unload aarch64
sig_id:         PKCS#7
signer:         IQSight Kernel Module Signing Key
sig_key:        2F:42:...:AB
sig_hashalgo:   sha512
signature:      99:D0:...
...
```

## Yocto patch

Add the following to the kernel recipe or .bbappend

編譯前將憑證複製到 kernel source code 的工作區

```python
FILESEXTRAPATHS:prepend := "${THISDIR}/files:"

SRC_URI = "file://signing_key.pem"

do_configure:append() {
    cp ${WORKDIR}/signing_key.pem ${S}/certs/signing_key.pem
}
```
